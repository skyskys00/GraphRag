# 开源软件许可证速查

## 为什么在意许可证

选型任何开源项目，第一件事是确认许可证：它决定了你能不能用、能不能商用、要不要开源自己的改动。尤其是 RAG 链条里每个组件（框架、数据库、解析器、模型）各有各的许可证。

## 宽松类（Permissive）

- **MIT**：几乎不加限制，署名即可，可随意商用闭源。LightRAG 就是 MIT。
- **Apache-2.0**：类似 MIT，额外提供专利授权条款，工程界最爱。多数国产开源（NebulaGraph、Milvus、bge 模型）用它。
- **BSD**：也属于宽松类。

## 强约束类（Copyleft）

- **GPLv3**：你修改并分发这个软件时，必须开放你的源码。Neo4j 社区版就是 GPLv3——**内部自用可以，改造后对外分发必须开源**。
- **AGPL**：比 GPL 更进一步，即使通过**网络服务**提供也触发源码开放义务。这意味着把 AGPL 组件做成 SaaS 时要格外小心。

## 常见的"坑"

1. 有些项目许可证是**定制版**（如 MinerU 的 Open Source License、Dify 的附加条款许可），不要想当然按纯 Apache 对待。
2. Elasticsearch 默认 AGPL/SSPL/EL-2.0 三选一，其中 SSPL 与 EL-2.0 不是 OSI 认证的开源协议，商用前务必查清楚。
3. 闭源 SaaS 也算一种"约束"（无源码但限制你的服务形态），选型时一并考虑。

口诀：**商用怕麻烦 → MIT/Apache；真传代码僧 → GPL/AGPL 要三思。**
