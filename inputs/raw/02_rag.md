# 检索增强生成（RAG）实战

## 为什么要 RAG

大语言模型的知识截止于训练数据，且容易"幻觉"。RAG（Retrieval-Augmented Generation）的思路是：回答问题时，先从外部知识库中检索相关内容，再把检索结果拼进提示词交给模型生成。这样既引入了私有领域知识，又能显著降低幻觉，还能做到引用溯源。

## 管线四大环节

一条典型的 RAG 管线包含：**文档解析**（把 PDF/Word 还原成结构化文本）、**切分（chunking）**（把长文切成适合检索与模型输入的块）、**向量化入库**（用 embedding 模型把块编码成向量，建索引）、**检索与生成**（把用户问题编码，用相似度召回最相关块，组装进提示词生成答案）。

## Chunking 的讲究

不是切得越小越好。块太小丢失语义，块太大超出模型与重排序的限制。业界经验是中文单块约 500–1000 字、块间留 10–15% 重叠；结构化文档（合同、论文）优先按标题层级切，而不是机械按字符数切。表格尽量一整块保留。

## 混合检索

纯向量检索对精确名词、编号、专名召回偏弱。更稳的做法是"关键词（BM25）+ 向量 + 图谱"多路召回后融合排序，例如 RRF（倒数排名融合）。中文场景的 embedding 常用 BGE、GTE 等系列模型。
