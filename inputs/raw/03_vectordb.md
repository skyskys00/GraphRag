# 向量数据库选型指南

## 为什么需要向量数据库

RAG 系统中的 embedding 向量需要高效地做最近邻检索。传统关系数据库不擅长这种高维相似度搜索，于是出现了专门的向量数据库，或者面向向量的索引扩展。

## 主流方案对比

- **FAISS**：Meta 开源的近似最近邻搜索库，可以嵌入到 Python 进程内使用，轻量、适合原型。
- **pgvector**：PostgreSQL 的向量扩展，让 SQL 数据库"顺便"支持向量检索，企业里最省运维的选择。
- **Milvus** / **Qdrant**：独立的分布式向量数据库，亿级向量场景的主战场，支持混合检索（稠密+稀疏+BM25）。Milvus 中文社区最活跃；Qdrant 部署轻、内置 RRF 融合。
- **Chroma**：嵌入式向量库，pip 装完即用，适合小规模学习和快速验证，但 HNSW 索引必须全量进内存，天花板低。

## 如何选

数据量百万以下、图省事，pgvector 或 FAISS 足够；个人小团队单机可以把多个向量库作为不同方案对比着用——LightRAG 等框架都支持一键切换底层向量存储。选型时除了性能，还要看许可证（能否商用）和中文维护活跃度。
