## 1. 背景与目标

现有 MVP 前端为 M7 零依赖单页（提问→答案+引用弹窗），已打通主链路。将 M8 改为**正式前端实现**（原 M8 评测顺延为 **M9**），要做出投入使用的 Web 问答界面。

**目标的验收形态**：打开浏览器即用，输入中文业务提问 → 答案逐 token 流式出现 → 答案中的引用 `[n]` 可点击 → 侧栏展示引用来源（文件名/页/原片段）→ 多轮追问自动带上下文；断流或后端报错时有可读提示，不白屏、不假死。

## 2. 用户与使用场景

| 项 | 说明 |
|---|---|
| 使用对象 | 内部业务/知识应用者（非技术为主）：查询会议纪要、办公用品月度汇总、季度复盘、投诉处理 SOP、产品需求文档等中文文档集 |
| 主要任务 | ①精确单轮问答（如「客户投诉的处理流程是怎样的？」）②多轮追问澄清 ③引用核验（答案依据来自哪些文档、哪些片段） |
| 成功标准 | 从输入到首 token 的等待期有明确反馈；流式渲染过程可读；引用可溯源，点击能定位到原文片段 |

## 3. 后端契约（需求的输入基础）

### 3.1 `POST /answer` — 非流式 JSON

**请求**

```jsonc
{ "query": "客户投诉的处理流程是怎样的？",
  "history": [ { "role": "user", "content": "..." }, { "role": "assistant", "content": "..." } ],
  "response_type": null }   // 可空，中文追加要求，例如"请分段回答，先总后分"
```

**响应 200**（`Answer` dict）

```jsonc
{
  "query": "...",
  "text": "带 [n] 引用的完整答案文本",
  "citations": [
    { "marker": 1, "text_unit_id": "…", "full_doc_id": "…",
      "file_path": "…", "title_path": null, "page_range": [1,1],
      "anchor": null, "snippet": "原文片段(前120字)", "score": 0.83 }
  ],
  "retrieval": { "query": "...", "results": [ ... ] },   // M5 原始检索，体积可能很大
  "meta": { "mode": "single-window", "used_chunks": 4,
            "context_tokens": 1212, "unmatched_markers": 0,
            "source_docs": ["文档A.pdf", "文档B.md"] }
}
```

**错误 500**：`{"detail": "HTTPException…"}`（FastAPI 默认错误体）。

### 3.2 `GET /answer/stream` — SSE 流式

Query 参数：`q`（问题，必填）、`history`（JSON 字符串，可空）、`response`（中文追加要求，可空）。

事件线（`event:` / `data:` 每帧），M7 实测单题即 `retrieved → delta×544 → citations → done`：

| 事件 | data 载荷 |
|---|---|
| `retrieved` | `{ "mode", "used_chunks", "context_tokens", "source_docs" }`（生成开始前的检索结果总览） |
| `delta` | `{ "text": "<当前增量>" }` —— **真 token 级增量**，数目约等于生成 token 数 |
| `citations` | `{ "citations": [ …同 §3.1 ], "meta": { "mode","used_chunks","unmatched_markers","source_docs" } }` |
| `done` | `{ "text": "<完整答案>", "query": "<原问题>" }` |
| `error` | `{ "message": "类型: 详情" }`（流中出现异常时兜底，之后流结束） |

SSE 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。

### 3.3 其他

- `GET /health` → `{"status":"ok"}`：前端可轮询/启动时探测服务可用性。
- `GET /` → 静态 WebUI（M7 壳）；**M8 落地后以 M8 工程产物替换/挂载**，契约不变。

### 3.4 契约约束对前端的含义

1. **sse 是 GET**：浏览器原生 `EventSource` 可直接订阅（自动重连），无需自己处理流读取；若改用 `fetch` 则需 `ReadableStream` 手解析 SSE。
2. **`history` 是前端拼接列表**：多轮由前端累计发送，后端无会话态。
3. **`response_type` 是追加要求文本**：非枚举，由用户输入/预设模板给出。
4. **`retrieval` 不可靠序列化**（可能含 numpy 标量）：前端不应依赖其字段做渲染；来源看 `meta.source_docs` / citations。
5. **`text` 是 LLM 生成内容**：前端必须按**纯文本**渲染（`textContent`），禁止 `innerHTML` 直插，防 XSS。

## 4. 功能需求

### 4.1 问答主流程

| 编号 | 需求 |
|---|---|
| FR-1 | 输入区支持多行问题 + Enter 快捷提交；提交后清空输入、禁用重复提交。 |
| FR-2 | 请求发出后立即进入「等待中」态：显示检索提示（「正在检索…」），收到 `retrieved` 后展示「共 N 个来源文档 / M 个片段已检索」。 |
| FR-3 | 收到 `delta` 即时追加渲染（逐 token 流式出现，不得等 `done` 才整段上屏）。 |
| FR-4 | 收到 `citations` 后，将正文中的 `[n]` 渲染为可点击引用角标，并构建引用列表。 |
| FR-5 | 收到 `done` 后锁定本条答案（结束流式、恢复输入可用）。 |
| FR-6 | 存在 `error` 事件或请求失败时，展示可读错误横幅，保留已生成/已检索内容（不整屏清空）。 |
| FR-7 | 提供「复制答案」「重问/重新生成」快捷操作。 |

### 4.2 引用与溯源

| 编号 | 需求 |
|---|---|
| FR-8 | 每条答案的引用角标 `[n]` 与 `citations.marker` 一一对应；点击角标 → 展开/跳转对应引用卡。 |
| FR-9 | 引用卡展示：文件名、页码/章节（`page_range`/`title_path`，无则隐藏）、原文片段（`snippet`）、文本单元 ID、相关分（`score` 可视对勾/低分弱化）。 |
| FR-10 | 引用卡的「定位」操作 → 以可读方式呈现原文片段（MVP 弹层/侧栏浮层承载 snippet；**PDF/原文定位为新开能力，见 FR-24**）。 |

| FR-32 | 边标签与节点详情：边展示关系描述文本（长文本前端截断、悬停显示完整）；节点详情展示实体描述 + 贡献该实体的来源文档列表（含每个实体关联的有效文档数）。 |

### 4.9 v3 扩展：多知识库（文档集隔离）

> 背景：现在只有一个隐式「默认知识库」，所有文档/问答/图谱混在一起。多知识库让用户按主题分组文档（如「项目A」「个人笔记」），**每个知识库 = 一个独立文档集合**——问答只搜当前库、文档管理只看当前库、图谱只画当前库、仪表盘显示该库统计。这是「多人共用一份数据会乱」之前的一层隔离；真实多人登录/权限（FR-21）仍维持二期不做。
> 后端配套：M4 存储层按**复用 LightRAG `workspace` 列**承载（一个 collection = 一个 `workspace` 值，利用 LightRAG 已有的行级隔离，而非在同 workspace 各实体表再加 `collection_id` 列）；M7 交互层新增知识库 CRUD 接口 + 现有业务接口（`/docs`、`/answer`、`/answer/stream`、`/graph`）的可选 `collection_id` 参数（缺省 `default`）。默认知识库 workspace = `default_ws`（现状零迁移），新建库 id 兼作 workspace 与目录名。
> **选型决策（2026-09-17 定）**：选「**复用 workspace 列**」方案，不选「同 workspace 加 `collection_id` 列」。理由：workspace 行级隔离是 LightRAG 原生能力（PG 全部实体表带 `workspace` 列、查询天然带 `WHERE workspace=$1`），不需要 fork 官方子模块改 DDL / 改 storage 实现，维护成本最低；每个 collection 共享同一个 ClientManager 连接池，同进程多实例 initialize 无冲突（已验证）；删库 = 清该 workspace 行 + 删目录，操作干净。若未来需要跨库检索，再考虑单 workspace 加列或 schema 分层。

| 编号 | 需求 |
|---|---|
| FR-33 | 左侧边栏顶部提供「当前知识库」切换器：展示库名，点击展开下拉（切换 / 新建 / 管理）；**切换后整个应用上下文切换**——问答只搜该库、文档管理只列该库文档、图谱只画该库、仪表盘显示该库统计。 |
| FR-34 | 知识库管理视图（切换器 → 管理）：列出全部知识库（名称 / 文档数 / 创建时间），支持新建（填名称即可，创建后自动切换）/ 重命名 / 删除。 |
| FR-35 | 删除知识库 = 删除其下全部文档 / TextUnit / 图谱 / 稀疏索引数据；删除前二次确认；**默认知识库不可删除**（MVP 禁删，转移后删除列入后续）。 |

- **会话视图**：上布局 + 引用面板 + 输入区（含附件上传按钮，FR-25）。
- **文档管理视图**：当前库文档列表（文件名/时间/状态 badge/删除按钮），FR-26/27。
- **知识图谱视图**（FR-29~32）：当前库全图力导向渲染，实体按 `entity_type` 着色（浅暖色系映射、未知类型灰）、可缩放/拖拽；点节点→右侧详情（实体名/类型/描述/来源文档 N 个）；边悬停→关系描述全文；空数据/加载中/加载失败三态；从引用「在图谱中查看」跳入并高亮该引用相关实体子图。

### 5.2 状态机（单条消息）

```
idle → submitting（检索中，可显示 retrieved 提示）
     → streaming（delta 追加中，含已收到的 citations）
     → complete（done 锁定） | error（错误横幅，内容保留可复制）
```

### 5.3 渲染约束

- **纯文本渲染**：答案与引用 snippet 一律走 `textContent` / 转义，禁止拼接 HTML 注入脚本（安全红线）。
- **引用角标解析**：对 `text` 中的 `[n]`（整数）做正则拆分渲染为按钮；**不得在 `done` 之前假设引用已完整**（citations 事件才定稿），流式期间 `[n]` 可暂按普通文本显示、`citations` 到达后替换为可点按钮。
- **滚动**：流式期间自动跟随底部；用户主动上翻则暂停跟随，回到底部恢复。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首 token 到屏耗时 ≤ 后端结果送达 + 一帧；长流（500+ delta）不卡顿、不丢字 |
| 兼容 | 现代 Chrome / Edge / Safari（EventSource、`fetch`、ES2020+） |
| 安全 | 不执行/不渲染 LLM 输出中的任何 HTML/脚本；不将密钥、路径泄露到 UI |
| 可访问性 | 输入区有 label；错误提示有 `role="alert"` 等可读语义 |
| 稳健 | 后端 500 / SSE 中断 / 非法 `history` 400 均有兜底提示，不白屏 |
| 契约对齐 | 前端以独立「契约样本」冒烟，后端契约变化时前端先于联调暴露断层 |
