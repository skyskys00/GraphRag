## 一、目标与范围

### 1.1 要解决的问题

1. **实体级图谱太密**：几页文档抽出几十上百个实体，全画出来是毛球，看不出重点。
2. **关系无区分**：所有边都是同一种颜色，用户看不出「这两个实体是什么关系」。
3. **缺宏观视图**：多文档时没有"文档之间关系"的视角，用户无法快速感知知识库的整体结构。

### 1.2 交付物

- **文档级图谱**（新视图）：节点=文档，边=概念关联/引用关系，话题聚类着色。
- **实体级图谱增强**（现有视图优化）：节点筛选 + 关系类型分类着色 + 类型过滤。
- **粒度切换交互**：文档级双击下钻到实体级、实体级有"返回文档级"入口。
- **后端接口**：`GET /graph?level=document` 新增文档级数据，`level=entity` 兼容现有行为。

### 1.3 不做的（本期）

- 内容相似度边（doc embedding）——等文档量级上来再评估。
- 同源导入边（元数据属性，不是内容关系，价值低）。
- LLM 小样本分类关系（先用关键词规则，不够再上）。
- 实体重名合并（同义实体归一化）——留待 v2，本期先靠筛选降低噪音。
- 双向联动（图谱→问答）——目前只有引用→图谱单向下钻，反向留待后续。

## 二、文档级图谱设计

### 2.1 节点（文档）

| 属性 | 来源 | 说明 |
|---|---|---|
| `id` | `doc_id` | 与文档管理的 doc_id 一致 |
| `label` | `filename` | 文档名，长文本截断 + 悬停全名 |
| `size` | 该文档的实体数（归一化） | 实体越多节点越大，直观体现"内容量" |
| `color` | 话题聚类编号 | 同一话题簇的文档同色，见 §2.4 |
| `doc_count` / `entity_count` | 文档元数据 | 悬停详情展示 |

### 2.2 边类型（两种边，均无向）

#### 类型 A：概念关联（主要边，必做）

- **定义**：两个文档共享的核心实体越多，关联越强。
- **算法**：Jaccard 相似度 = |A∩B| / |A∪B|，阈值 > 0.05（约 1-2 个共享实体起）才画边。
- **粗细映射**：边的线宽 = Jaccard 相似度（归一化到 1-6px）。
- **数据来源**：`lightrag_graph_nodes` 每个节点的 `docs[]` 归属（或 `lightrag_doc_chunks` → 实体 → 文档 关联表）。
- **后端计算**：一次 SQL 聚合即可，文档数 < 100 时毫秒级。
- **悬停展示**：共享实体数 + 前 5 个共享实体名。

#### 类型 B：引用关系（次要边，必做）

- **定义**：文档 A 的文本中明确提到了文档 B 的名称（或文件名、编号）。
- **算法**：对每个文档名（去掉扩展名、提取核心名）做正则匹配，扫描其他文档的 TextUnit 文本。
  - 匹配策略：文件名去扩展名 → 去标点 → 转小写 → 在其他文档 chunk 文本中搜索出现。
  - 同时支持编号匹配：如 `PRD V2.1`、`SOP-001` 这类格式。
- **边样式**：实线 + 箭头方向（A 引用 B → 有向箭头），深色描边区别于概念关联。
- **边的数量**：通常很少（大部分文档互不引用），作为"强关系"高亮。
- **悬停展示**：引用次数 + 引用片段摘录（第一条匹配的 snippet）。

> 注：如果文档库中没有交叉引用，这条边自动为 0，不影响整体布局——退化到纯概念关联也完全可用。

### 2.3 两种边的视觉区分

| 边类型 | 颜色 | 线型 | 粗细 | 是否有向 |
|---|---|---|---|---|
| 概念关联 | 中性灰（#b8a99a） | 实线 | 随 Jaccard 变（1-6px） | 无向 |
| 引用关系 | 深棕色（#8b5a2e） | 实线 + 箭头 | 固定 2px | 有向 |

### 2.4 话题聚类（社区发现，节点着色）

- **算法**：在概念关联图上跑 **Louvain 社区发现**（Python `python-louvain` / `community` 库，或前端 `ngraph.forcelayout` + 社区发现）。
- **输出**：每个文档一个 `cluster_id`（0, 1, 2...），映射到 6-8 种柔和颜色。
- **计算位置**：后端实时算（文档数 < 200 时毫秒级），前端拿到 `cluster_id` 直接着色。
- **价值**：让"毛球"变成"几簇"，用户一眼看出知识库大概分几大类。
- **颜色数量**：预定义 8 色调色板（柔和暖色系，与整体浅暖风格统一），超过 8 簇时循环使用。
- **legend**：右侧或顶部显示话题图例，hover 显示该簇文档数，点击可高亮该簇。

### 2.5 交互

- 默认显示文档级图谱（当文档数 ≥ 3 时；少于 3 篇直接进实体级）。
- **双击文档节点** → 下钻到该文档的实体级图谱（等价于当前的 `doc_id` 过滤）。
- **顶部粒度切换**：`文档视图` / `实体视图` 分段控件，随时切换。
- 实体级视图顶部加一个"返回文档级"按钮（在有文档上下文时显示）。
- 边悬停显示详情（概念关联：共享实体列表；引用关系：引用片段）。
- 节点悬停显示文档详情（文件名、实体数、所属话题）。

## 三、实体级图谱优化

### 3.1 节点筛选（解决毛球问题）

三层筛选，从粗到细：

#### 第一层：核心节点模式（默认）

- 默认显示 **top 60 个实体**（按 PageRank 排序）。
- 保留这些节点**之间的边**（不保留被筛掉节点的边，避免"悬空边"）。
- 底部加切换：`核心实体 (60)` / `全部实体`，用户可手动切换。
- 节点总数 < 40 时直接显示全部，不做筛选。
- **PageRank 计算位置**：后端导出时算（Python `networkx` 或前端 `ngraph.pagerank`），后端算更稳定。

#### 第二层：类型过滤

- 顶部加实体类型筛选（多选 chip 或下拉）：`全部 | 组织 | 人物 | 产品/项目 | 概念 | 事件 | 地点 | 其他`。
- 点击类型可隐藏/显示该类实体。
- 类型从 LightRAG 抽取的 `entity_type` 字段直接取（已有数据，无需额外处理）。
- 类型名归一化：LightRAG 抽的类型名可能不统一（`organization` / `org` / `组织`），后端做一次映射归并到 6-7 大类。

#### 第三层：搜索定位

- 图谱顶部加搜索框，输入实体名 → 高亮匹配节点 + 自动聚焦。
- 这个是增强项，优先级低于前两层。

### 3.2 关系类型分类（6 类 + 关键词规则）

#### 分类体系

| 编号 | 类型名 | 颜色 | 关键词触发（中文） |
|---|---|---|---|
| 1 | 归属/组成 | 蓝色系 `#5b8def` | 属于、组成、下设、分公司、部门、隶属于、包含、成员 |
| 2 | 动作/执行 | 绿色系 `#6aa96a` | 负责、处理、执行、推进、开展、管理、运营、生产、销售 |
| 3 | 因果/影响 | 红色系 `#c46453` | 导致、带来、提升、影响、因为、所以、促进、推动、使得、造成 |
| 4 | 时间/先后 | 紫色系 `#9a7bc4` | 之前、之后、随后、接着、下一步、首先、然后、最后、期间 |
| 5 | 同义/相关 | 灰青色 `#6a9ea3` | 又称、简称、即、也就是、又名、亦称、俗称 |
| 6 | 属性/数值 | 橙色系 `#d4915c` | 为、达到、等于、占比、共计、总计、金额、数量、比例 |
| 0 | 未分类 | 默认灰 `#a89b8d` | 匹配不到以上关键词 |

#### 实现方案（三期递进，本期做方案 A）

**方案 A：关键词规则分类（本期做，0.5 天）**
- 后端 `graph.py` 在导出边时，对 `description` 字段跑正则关键词匹配。
- 命中第一个类型即归类（按上表顺序，优先级从高到低）。
- 输出边增加 `rel_type` 字段（类型编号 + 类型名）。
- 预期准确率：60-70%。

**方案 B：LLM 小样本分类（后续迭代，预计 1 天）**
- 在建库阶段或图谱导出时，对每条关系调 LLM 从 6 类中选一类。
- 用 few-shot prompt（给 3-5 个例子），成本低、质量高。
- 预期准确率：85-90%。
- 触发条件：方案 A 分类后"未分类"占比 > 40%，或用户反馈关系类型不准。

**方案 C：保持自由文本 + 悬停展示（已存在，做基础层）**
- 边的 `description` 字段保留，悬停始终显示完整描述。
- 分类着色是"一眼区分"的增强，不替代详细描述。

#### 视觉呈现

- 边的颜色 = 关系类型颜色（上表）。
- 边粗细不变（统一 1.5px，关系类型不靠粗细区分）。
- 右上角 legend 显示 6 类关系的颜色图例，点击可隐藏/显示某类关系。
- 悬停边时显示：关系类型名 + 完整描述文本。

## 四、后端接口设计

### 4.1 接口变更

`GET /graph` 新增参数，向下兼容：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `collection_id` | str | `default` | 知识库 id（已有） |
| `doc_id` | str | 空 | 单文档过滤（已有），仅 level=entity 时有效 |
| `level` | `document` \| `entity` | `entity` | 图谱粒度 |
| `top_n` | int | 0 | level=entity 时有效，0=全部，>0 取 PageRank top_n |

### 4.2 文档级返回格式

```jsonc
{
  "level": "document",
  "nodes": [
    {
      "id": "doc_id_1",
      "label": "季度销售业绩复盘报告.pdf",
      "entity_count": 47,
      "cluster_id": 0,
      "created_at": "2026-09-15T..."
    }
  ],
  "edges": [
    {
      "source": "doc_id_1",
      "target": "doc_id_2",
      "type": "concept",       // concept | citation
      "weight": 0.23,          // Jaccard，仅 concept 边
      "shared_entities": ["华东大区", "毛利率", "经销商"],   // 前 5 个，仅 concept
      "snippet": "如《Q3 复盘》所述..."  // 仅 citation 边，引用片段摘录
    }
  ],
  "clusters": [
    { "id": 0, "name": "销售运营", "doc_count": 3, "color": "#..." }
  ]
}
```

> cluster 的 name 自动生成：取该簇中最高频的 2-3 个实体名拼接（如「销售-华东-渠道」），作为话题标签。

### 4.3 实体级返回格式（增量字段）

边新增 `rel_type` 和 `rel_type_name`：

```jsonc
{
  "level": "entity",
  "nodes": [ /* 不变，新增 pagerank 字段可选 */ ],
  "edges": [
    {
      "source": "...",
      "target": "...",
      "description": "...",   // 已有
      "rel_type": 1,           // 新增：类型编号
      "rel_type_name": "归属"  // 新增：类型中文名
    }
  ]
}
```

## 五、前端实现要点

### 5.1 文档级图谱渲染

- 继续用 AntV G6（v5.1），力导向布局。
- 节点用圆角矩形（`rect` 类型），显示文档名。
- 节点大小按 `entity_count` 映射。
- 节点颜色按 `cluster_id` 从调色板取。
- 边：概念关联用灰线、粗细映射 weight；引用关系用深棕有向箭头。
- 双击节点 → 切到实体级 + 设置 `doc_id` 过滤。

### 5.2 实体级增强

- 边着色按 `rel_type`。
- 新增类型过滤 panel（顶部或侧边）：实体类型 + 关系类型，两组过滤。
- 新增"核心/全部"切换按钮（top_n 参数切换）。
- 新增"返回文档级"按钮（当从文档级下钻来时显示）。

### 5.3 legend 与图例

- 右上角浮动 legend：话题聚类（文档级显示） + 关系类型（实体级显示）。
- 点击 legend 项可高亮/隐藏对应类。

## 七、风险与取舍

1. **关键词分类不准** → 方案 A 预期 60-70%，能用但不完美；不够再上 LLM 分类（方案 B）。
2. **引用关系可能为 0** → 不影响，退化到纯概念关联也成立。
3. **PageRank 前端算 vs 后端算** → 优先后端算（稳定、不阻塞主线程）；前端有 `ngraph.pagerank` 备选。
4. **话题聚类无语义标签** → 自动取高频实体名拼接，可能不够准；用户能看懂颜色分组即可，不追求完美命名。
5. **doc_id 过滤下的 PageRank 无意义** → 单文档实体少（< 30）时不做筛选，直接全显示。
6. **性能**：文档级图谱文档数 < 200 时，所有计算（Jaccard + Louvain + PageRank）均在毫秒~秒级，无需缓存；超过 200 篇再考虑缓存。

## 八、与现有架构的关系

- 不新增数据库表，所有文档级数据**实时派生**（从实体归属关系 + 文档 TextUnit 文本计算），删除/新增文档时自动生效，无一致性问题。
- 不改 LightRAG 子模块，纯外层包装。
- 与 collection 隔离完全兼容——每个 collection 的图谱独立计算。
- 与引用→图谱下钻联动兼容——下钻到的是实体级视图，不受影响。
