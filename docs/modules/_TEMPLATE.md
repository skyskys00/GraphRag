# 模块记录模板（_TEMPLATE）

> 用法：新建模块记录时复制本文件，改为 `Mx_名称.md`，只留 4 节 + 头部状态行。
> 目标：**轻、单一事实源、好维护**。别再把「规划流程」「架构复述」「历史版本流水」写进模块文件。

## 头部状态行（5 行内）

```markdown
# Mx 模块记录：<一句话职责>

> 状态：**<当前版本 + 一句话落地点>**（日期）。
> 契约：<输入 → 输出，引用 M0_contracts/ 或链接>
> 依据：<引用 ARCHITECTURE.md §x / FRAMEWORK_NOTES.md §x>
> 运行：<复现命令 / 或见 docs/CHANGELOG.md>
```

## 1. 接口契约

- 输入 → 输出（数据流一句话）；
- 代码结构表：`文件` | `职责`（只列关键文件）；
- 依赖哪些上游契约、给哪些下游消费（用链接，不重述契约内容）。

## 2. 关键决策

- 每条决策 = **结论 + 一句理由**（尤其踩坑后定案、和直接人相反的取舍）；
- 「调研过程/备选方案」只留结论行，展开内容引用调研文档（如 PARSER_COMPARISON.md）。

## 3. 已知坑与待办

- 已知坑：踩过、下次必读的坑（**每个坑一句话**，详情可给代码位置）；
- 待办 / TODO：明确「暂不做」的留一行，避免未来重复讨论。

## 4. 版本

- 当前版本号在状态行；
- **版本历史统一记 `docs/CHANGELOG.md`**，本文件只留一行：
  `变更记录：见 docs/CHANGELOG.md（v1.0 历史 / v2.0 文档重做后按新约定登记）`
